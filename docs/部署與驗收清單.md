# 部署與驗收清單

狀態說明：
- **本機已測**：已在開發環境以本機 PostgreSQL（套用正式 migration）＋正式 Edge Function 程式＋ Chromium 瀏覽器自動化實際操作通過，詳見 [測試報告](測試報告.md)。
- **尚未實測**：需要真正的 Supabase 專案與 GitHub Pages 網址才能驗證，請部署後依「實測方法」勾選。

本機測試環境並不是真正的 Supabase（Auth 與 Storage 為相容模擬），因此 **所有項目在正式網址上都應再實測一次**。

## E. 正式環境安全實測（部署後請做一次）

**C-1 私有原圖不能公開取得**
1. Supabase Dashboard → Storage → originals → 任一檔案 → 複製路徑
2. 瀏覽器開 `https://<專案>.supabase.co/storage/v1/object/public/originals/<路徑>`
3. 應看到錯誤（Bucket not found 或 400），**不能**看到圖片

**C-2 訪客不能讀寫資料**（電腦終端機）
```bash
URL=https://<專案>.supabase.co
KEY=<anon 或 publishable key>
# 應回 401/403 錯誤：
curl -s "$URL/rest/v1/images?select=original_path" -H "apikey: $KEY"
curl -s -X POST "$URL/rest/v1/rpc/set_download_password" -H "apikey: $KEY" -H "Content-Type: application/json" -d '{"p_new_password":"hack123"}'
curl -s -X POST "$URL/functions/v1/download" -H "Content-Type: application/json" -d '{"action":"sign","all":true}'
# 應正常回傳公開資料：
curl -s "$URL/rest/v1/images?select=title" -H "apikey: $KEY"
```

**C-3 已登入但未授權的帳號**
1. Authentication → Users 建立一個測試帳號（不要登記進 admins）
2. 用它登入 `#/admin` → 應顯示「此帳號沒有管理權限」
3. 測完刪除該帳號

**C-4 暴力猜測限制**
在下載視窗連續輸入 5 次錯誤密碼 → 第 6 次應顯示「密碼錯誤次數過多，請約 N 分鐘後再試」。
（同一個網路的其他粉絲也會被暫時鎖定 15 分鐘；換密碼可立即解除。）
